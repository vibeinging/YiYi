## 1. Alembic 数据库管理脚本

**文件**: `backend/scripts/alembic_manager.py`

### 功能概述

这是一个全功能的数据库迁移管理工具，支持：
- 数据库版本初始化和升级
- 迁移文件创建和回滚
- 多环境版本管理（开发、测试、生产）
- 渐进式部署流程
- 迁移前的备份和兼容性检查
- 版本一致性验证

### 核心功能

#### 1.1 初始化数据库

**命令**:
```bash
python scripts/alembic_manager.py init
```

**说明**:
- 检查数据库是否已初始化
- 若未初始化，自动升级至最新版本
- 若已初始化，显示当前版本号

**示例输出**:
```
🗄️ 初始化数据库...
📊 当前版本: a1b2c3d4e5f6
✅ 数据库初始化完成
```

#### 1.2 创建迁移文件

**命令**:
```bash
python scripts/alembic_manager.py migrate "迁移描述"
```

**参数**:
- `message`: 迁移的描述信息，使用引号括起来

**示例**:
```bash
# 创建新表迁移
python scripts/alembic_manager.py migrate "添加用户角色表"

# 修改字段迁移
python scripts/alembic_manager.py migrate "添加用户邮箱字段"
```

**自动检查**:
- 每次创建迁移后，脚本自动验证兼容性
- 检测危险操作：`DROP COLUMN`、`DROP TABLE`、`ALTER COLUMN` 等

#### 1.3 升级数据库

**命令**:
```bash
# 升级到最新版本
python scripts/alembic_manager.py upgrade

# 升级到指定版本
python scripts/alembic_manager.py upgrade abc123def456
```

**参数**:
- `revision`: 目标版本（可选，默认 `head` 即最新版本）

#### 1.4 回滚迁移

**命令**:
```bash
# 回滚1步（撤销最后一次迁移）
python scripts/alembic_manager.py downgrade

# 回滚多步
python scripts/alembic_manager.py downgrade 3
```

**参数**:
- `step`: 回滚步数（可选，默认 1）

#### 1.5 版本查询

**显示当前版本**:
```bash
python scripts/alembic_manager.py current
```

**显示迁移历史**:
```bash
python scripts/alembic_manager.py history
```

#### 1.6 环境管理

##### 检查多环境版本一致性

```bash
python scripts/alembic_manager.py check
```

**功能**:
- 检查 DEVELOPMENT、TESTING、PRODUCTION 三个环境的数据库版本
- 验证所有环境是否使用相同版本
- 显示警告如果版本不一致

**示例输出**:
```
🔍 检查各环境数据库版本...

📊 检查 DEVELOPMENT 环境...
   当前版本: a1b2c3d4e5f6

📊 检查 TESTING 环境...
   当前版本: a1b2c3d4e5f6

📊 检查 PRODUCTION 环境...
   当前版本: a1b2c3d4e5f6

==================================================
版本汇总:
  ✅ DEVELOPMENT: a1b2c3d4e5f6
  ✅ TESTING: a1b2c3d4e5f6
  ✅ PRODUCTION: a1b2c3d4e5f6

✅ 所有环境版本一致
```

##### 验证迁移兼容性

```bash
python scripts/alembic_manager.py validate
```

**功能**:
- 扫描所有迁移文件
- 检测潜在的破坏性操作
- 列出兼容性问题

#### 1.7 部署操作

##### 安全部署（推荐）

```bash
# 部署到指定环境
python scripts/alembic_manager.py deploy DEVELOPMENT

# 部署到生产环境并升级到特定版本
python scripts/alembic_manager.py deploy PRODUCTION --target abc123def456
```

**部署流程**:
1. 设置目标环境
2. 检查当前版本
3. **验证迁移兼容性**
4. **备份数据库**（仅生产环境）
5. 执行迁移
6. 验证新版本

**参数**:
- `env`: 目标环境 (`DEVELOPMENT`、`TESTING`、`PRODUCTION`)
- `--target`: 目标版本（可选，默认 `head`）

**示例**:
```bash
# 部署到开发环境
python scripts/alembic_manager.py deploy DEVELOPMENT

# 部署到生产环境
python scripts/alembic_manager.py deploy PRODUCTION
```

##### 渐进式部署

```bash
python scripts/alembic_manager.py progressive
```

**功能**:
- 按顺序部署到所有三个环境
- 每个环境部署前需要手动确认（除开发环境外）
- 任何环节失败则中止后续部署

**部署顺序**: DEVELOPMENT → TESTING → PRODUCTION

**示例**:
```bash
$ python scripts/alembic_manager.py progressive
🔄 开始渐进式部署: DEVELOPMENT -> TESTING -> PRODUCTION

==================== 第 1/3 步: DEVELOPMENT ====================
📊 当前版本: a1b2c3d4e5f6
✅ DEVELOPMENT 环境部署成功

==================== 第 2/3 步: TESTING ====================
确认部署到 TESTING 环境？(y/N): y
📊 当前版本: a1b2c3d4e5f6
✅ TESTING 环境部署成功

==================== 第 3/3 步: PRODUCTION ====================
确认部署到 PRODUCTION 环境？(y/N): y
💾 备份 PRODUCTION 环境数据库...
✅ 数据库备份成功: backup_PRODUCTION_20240101_120000.sql
✅ PRODUCTION 环境部署成功

🎉 渐进式部署完成！
```

##### 回滚指定环境

```bash
# 回滚1步
python scripts/alembic_manager.py rollback PRODUCTION

# 回滚多步
python scripts/alembic_manager.py rollback PRODUCTION --steps=3
```

**参数**:
- `env`: 环境名称 (`DEVELOPMENT`、`TESTING`、`PRODUCTION`)
- `--steps`: 回滚步数（可选，默认 1）

**注意**: 生产环境回滚前会自动备份数据库

### 常见场景

#### 场景1: 新增表结构

```bash
# 1. 创建迁移文件
python scripts/alembic_manager.py migrate "添加订单表和订单项表"

# 2. 编辑 migrations/versions/*.py 文件，定义表结构

# 3. 本地测试升级
python scripts/alembic_manager.py upgrade

# 4. 检查版本
python scripts/alembic_manager.py current

# 5. 部署到生产环境
python scripts/alembic_manager.py deploy PRODUCTION
```

#### 场景2: 生产环境出现问题需要回滚

```bash
# 1. 查看当前版本和历史
python scripts/alembic_manager.py current
python scripts/alembic_manager.py history

# 2. 执行回滚（会先备份）
python scripts/alembic_manager.py rollback PRODUCTION --steps=2

# 3. 验证回滚结果
python scripts/alembic_manager.py current
```

#### 场景3: 多环境版本同步

```bash
# 1. 检查当前状态
python scripts/alembic_manager.py check

# 2. 如果版本不一致，使用渐进式部署同步
python scripts/alembic_manager.py progressive
```

### 配置说明

- **环境变量**: `CONFIG_NAME`（`DEVELOPMENT`、`TESTING`、`PRODUCTION`）
- **配置文件**: `config/config.yaml` - 包含各环境数据库连接信息
- **迁移目录**: `migrations/versions/` - 存储所有迁移文件
- **备份目录**: 当前目录 - 生产环境备份文件会保存在这里

### 注意事项

1. **破坏性操作检查**: 脚本会检查是否含有 `DROP COLUMN`、`DROP TABLE` 等危险操作，需要谨慎处理
2. **备份策略**: 生产环境部署前必须备份，备份文件名格式为 `backup_PRODUCTION_YYYYMMDD_HHMMSS.sql`
3. **版本一致性**: 生产部署前应确保所有环境版本一致
4. **渐进式部署**: 建议使用此方式部署到生产环境，可逐步验证

## 2. 配置检查脚本

**文件**: `backend/scripts/check_config.py`

### 功能概述

验证系统配置的正确性和一致性，确保：
- `config.yaml` 和 `alembic.ini` 配置同步
- 数据库连接配置有效
- 环境配置正确应用

### 使用方法

```bash
python scripts/check_config.py
```

**无参数**，直接运行即可检查所有配置。

### 检查内容

#### 1. 配置文件加载
- 验证 `config.yaml` 是否能正确加载
- 显示当前环境（`CONFIG_NAME`）
- 显示应用和同步数据库 URL

#### 2. Alembic 配置
- 读取 `alembic.ini` 中的数据库配置
- 验证 `migrations/env.py` 中的动态配置覆盖

#### 3. 一致性检查
- 验证 Alembic 使用了正确的配置源
- 确认配置来源统一为 `config.yaml`

#### 4. 安全检查
- 检测是否使用本地数据库（localhost、127.0.0.1）
- 检测是否使用测试数据库
- 提示生产数据库的使用

### 示例输出

```
🔍 数据库配置检查
==================================================
✅ 配置文件加载成功
📁 当前环境: DEVELOPMENT
📊 应用数据库URL: sqlite:///./yiw.db
🔄 同步数据库URL: sqlite:///./yiw.db
📝 Alembic.ini中的URL: sqlite:///./yiw.db

🔄 配置覆盖过程:
📝 alembic.ini原始URL: sqlite:///./yiw.db
✅ migrations/env.py将覆盖为: sqlite:///./yiw.db

🔒 一致性检查:
✅ Alembic使用migrations/env.py动态加载配置
✅ 配置源统一：config.yaml
✅ alembic.ini中的配置仅作为占位符

⚠️  警告: 正在使用本地数据库

🎉 配置检查完成，一切正常！
```

### 常见场景

#### 场景1: 新环境初始化
```bash
# 设置环境变量
export CONFIG_NAME=PRODUCTION

# 检查配置是否正确
python scripts/check_config.py
```

#### 场景2: 部署前验证
```bash
# 确保使用正确的数据库
python scripts/check_config.py
```

## 3. 系统初始化脚本

**文件**: `backend/scripts/init_system.py`

### 功能概述

整合系统初始化流程，一站式完成：
- 公司创建（单租户/多租户）
- 预置角色初始化
- 管理员用户创建

### 使用方法

```bash
# 默认配置（推荐首次使用）
python scripts/init_system.py --default

# 交互式
python scripts/init_system.py

# 自定义管理员
python scripts/init_system.py -u admin -p yourpassword

# 完整指定
python scripts/init_system.py --company-name "公司名" --company-code mycode -u admin -p 123456
```

### 命令行参数

| 参数 | 简写 | 说明 | 默认值 |
|-----|------|------|--------|
| `--default` | `-d` | 使用默认配置 | - |
| `--company-name` | - | 公司名称 | 默认公司 |
| `--company-code` | - | 公司标识 | default |
| `--username` | `-u` | 管理员用户名 | agentic |
| `--password` | `-p` | 管理员密码 | agentic_2025 |

### 执行流程

#### Step 1: 公司初始化

无公司时自动创建默认公司；有公司时交互选择：
```
发现 1 个现有公司:
  [1] 默认公司 (default)
  [N] 创建新公司

请选择 (输入数字或 N): 1
```

#### Step 2: 角色初始化

从 `config/preset_roles.yaml` 读取预置角色并创建：
```
📦 步骤 2: 初始化预置角色
----------------------------------------
✅ 已创建角色: 项目管理员 (project_admin)
✅ 已创建角色: 开发者 (developer)
✅ 已创建角色: 分析师 (analyst)
✅ 已创建角色: 访客 (viewer)
```

#### Step 3: 管理员用户

交互式或命令行创建管理员：
```
📦 步骤 3: 创建管理员用户
----------------------------------------
请输入管理员用户名: admin
请输入管理员密码: ••••••••
请确认密码: ••••••••
✅ 管理员用户创建成功: admin
```

### 常见场景

#### 场景1: 快速初始化

```bash
# 1. 初始化数据库
python scripts/alembic_manager.py init

# 2. 初始化系统（使用默认配置）
python scripts/init_system.py --default
```

#### 场景2: 自定义初始化

```bash
python scripts/init_system.py --company-name "我的公司" --company-code mycompany -u admin -p securepass
```

### 注意事项

1. **幂等设计**: 重复执行会跳过已存在的公司、角色和用户
2. **密码安全**: 使用 `getpass` 隐藏密码输入
3. **角色配置**: 可通过 `config/preset_roles.yaml` 自定义角色

## 4. 创建邀请码脚本

**文件**: `backend/scripts/create_invite_key.py`

### 功能概述

快速生成用户邀请码，支持：
- 批量生成邀请码
- 自定义描述和使用次数限制
- 命令行参数传递

### 使用方法

#### 基础用法

```bash
# 创建单个邀请码（默认）
python scripts/create_invite_key.py
```

#### 带参数的用法

```bash
# 自定义描述
python scripts/create_invite_key.py --description "VIP用户邀请码"

# 自定义最大使用次数
python scripts/create_invite_key.py --max-uses 5

# 组合参数

```

### 参数说明

| 参数 | 类型 | 默认值 | 说明 |
|-----|-----|--------|------|
| `--description` | string | "系统生成的邀请码" | 邀请码描述 |
| `--max-uses` | int | 1 | 邀请码最大使用次数 |

### 示例

```bash
# 创建多次使用的邀请码
python scripts/create_invite_key.py --description "内部测试邀请码" --max-uses 100

| 特性 | `init_system.py` | `create_invite_link.py` |

| 功能 | 系统初始化（公司+角色+管理员） | 邀请码生成 |
| 使用场景 | 首次部署 | 日常邀请用户 |
| 交互性 | 支持交互式和命令行 | 命令行参数 |

```

```bash

```

## 6. VexDB 索引管理脚本

**文件**: `backend/scripts/create_vexdb_indexes.py`

### 功能概述

完整的向量数据库索引管理工具，支持：
- **两种索引类型**:
  - 向量索引（HybridANN）- 用于语义搜索
  - 全文检索索引（BM25）- 用于关键词搜索
- **四种操作**: 创建、删除、重建、查询
- **灵活的作用域**: 全部表、指定表、单个索引

### 支持的表和索引

#### 向量索引 (HybridANN)

| 表名 | 索引名 | 向量字段 | 用途 |
|-----|--------|---------|-----|
| `table_metadata` | `idx_table_metadata_embedding` | embedding | 数据表元数据搜索 |
| `column_metadata` | `idx_column_metadata_embedding` | embedding | 数据列元数据搜索 |
| `sql_examples` | `idx_sql_examples_embedding` | embedding | SQL 示例搜索 |
| `entity_mappings` | `idx_entity_mappings_embedding` | embedding | 实体映射搜索 |
| `business_rules` | `idx_business_rules_embedding` | embedding | 业务规则搜索 |

#### 全文检索索引 (BM25)

| 表名 | 索引名 | 索引字段 | 用途 |
|-----|--------|---------|-----|
| `table_metadata` | `idx_table_metadata_keywords_fulltext` | keywords | 表名和描述关键词搜索 |
| `column_metadata` | `idx_column_metadata_keywords_fulltext` | keywords | 字段名和描述关键词搜索 |
| `business_rules` | `idx_business_rules_fulltext` | embedding_desc, content, keywords | 规则全文搜索 |

### 索引参数说明

#### 向量索引参数

```sql
CREATE INDEX idx_name ON table_name
USING hybridann (embedding floatvector_cosine_ops, filter_column)
WITH (
  parallel_workers = 8,      -- 并行工作线程数
  m = 16,                    -- HNSW 图的邻接度
  ef_construction = 200      -- 构建时的搜索范围
)
```

**参数含义**:
- `parallel_workers`: 更大值 = 更快构建但更多内存占用
- `m`: 影响查询速度和准确度的平衡
- `ef_construction`: 更大值 = 更好的向量质量但更慢的构建

#### 全文检索索引参数

```sql
CREATE INDEX idx_name ON table_name
USING fulltext(column1, column2, ...)
WITH (
  DICTS = cn_tokenizer,     -- 中文分词器
  ALGORITHMS = BM25         -- BM25 排序算法
)
```

### 常见问题

#### Q: 索引创建失败

**可能原因**:
1. 表不存在 - 检查数据库是否正确初始化
2. 列不存在 - 检查表结构是否正确
3. 权限不足 - 检查数据库用户权限

**解决方案**:
```bash
# 1. 检查表结构
python scripts/create_vexdb_indexes.py --action list --verbose

# 2. 查看详细错误（检查日志）
python scripts/create_vexdb_indexes.py --action create --type vector

# 3. 重建特定表的索引
python scripts/create_vexdb_indexes.py --action rebuild --type all --tables table_metadata
```

#### Q: 向量搜索性能差

**可能原因**:
1. 向量索引未创建或已删除
2. 索引参数不优化

**解决方案**:
```bash
# 1. 验证索引存在
python scripts/create_vexdb_indexes.py --action list

# 2. 重建索引（使用更好的参数）
python scripts/create_vexdb_indexes.py --action rebuild --type vector
```

## 错误排查指南

### 常见错误和解决方案

| 错误 | 原因 | 解决方案 |
|-----|-----|---------|
| `ModuleNotFoundError: No module named 'config'` | Python 路径不正确 | 确保在 `backend` 目录运行脚本 |
| `database connection failed` | 数据库未启动或配置错误 | 检查 `config.yaml` 和数据库连接 |
| `alembic command not found` | Alembic 未安装 | 运行 `pip install -r requirements.txt` |
| `permission denied` | 文件权限不足 | 运行 `chmod +x scripts/*.py` |

### 获取更多帮助

- 检查脚本帮助信息: `python scripts/xxx.py -h` 或 `--help`
- 查看日志输出: 脚本使用颜色化日志，✅ 表示成功，❌ 表示失败
- 启用详细日志: 大多数脚本支持 `--verbose` 参数显示详细信息
