## 概述

`TaskService` 是 YiW 系统中负责异步任务管理的核心服务。它实现了以下关键功能：

- **任务生命周期管理**: 从提交、执行、完成到失败的完整状态管理
- **异步后台执行**: 使用 `asyncio.create_task()` 在后台执行长时任务
- **流式结果推送**: 通过 Redis Stream 和内存队列实现实时推送
- **会话消息持久化**: 将 Agent 执行结果保存到数据库会话

### 核心概念

| 概念               | 说明                                       |
| ------------------ | ------------------------------------------ |
| **Task**           | 数据库模型，存储任务的基本信息和状态       |
| **StreamCallback** | 流式回调对象，Agent 使用它实时推送执行过程 |
| **Redis Stream**   | 持久化事件流，支持断线重连                 |
| **内存队列**       | 实时事件推送给在线用户                     |
| **SSE Stream**     | Server-Sent Events，前端接收流式数据       |

## 核心架构

### 系统角色关系

```
Frontend (Vue3)
    ↓
FastAPI 路由 (POST /api/sessions/chat)
    ↓
TaskService.submit_task()
    ├─→ 创建 Task 记录到数据库
    └─→ 启动后台任务 _execute_task_background()
             ↓
         初始化 → 执行 NL2SQL Agent → 保存结果
             ↓
         推送事件到 Redis Stream
             ↓
         推送事件到内存队列
    ↓
TaskService.generate_task_stream()
    ↓
Front-end SSE 连接
    ├─→ 内存队列 (实时)
    └─→ Redis Stream (重连恢复)
```

### 关键设计特点

**1. 双推送机制（Dual Push）**

- 所有事件同时推送到 Redis Stream（持久化）和内存队列（实时）
- Redis Stream 用于用户重新连接时的事件恢复
- 内存队列用于在线用户的实时推送

**2. 状态驱动模式**

- 每个任务都有明确的状态转移：`pending` → `running` → `completed`/`failed`
- 状态变化都会触发相应事件推送

**3. 内容块去重机制**

- 从 Redis Stream 读取时，使用 `seen_content_ids` 集合去重
- 相同 `content_id` 的多次推送会被合并（文本累积，表格替换）

**4. 简化的 StreamCallback**

- Linus 重构：仅需 3 个参数（task_id、session_id、user_id）
- 不需要单独的内容收集器，Agent 直接调用回调函数

## 任务生命周期

### 完整生命周期流程

```
┌─────────────────────────────────────────────────────────────────┐
│ 1. 提交阶段 (submit_task)                                        │
│    ✓ 创建 Task 记录，状态='pending'                             │
│    ✓ 立即返回 task_id 给前端                                     │
│    ✓ 启动后台任务（不阻塞）                                      │
└─────────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────────┐
│ 2. 初始化阶段 (_initialize_task)                                │
│    ✓ 推送 task_started 事件                                      │
│    ✓ 更新状态为 'running'                                        │
│    ✓ 从数据库加载 Task 记录                                      │
│    ✓ 验证任务是否存在                                            │
└─────────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────────┐
│ 3. 上下文准备阶段                                                 │
│    ✓ 获取会话历史消息（session_context）                        │
│    ✓ 解析 user_message 和 database_id                           │
│    ✓ 推送 processing_started 事件                               │
└─────────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────────┐
│ 4. 执行阶段 (_execute_nl2sql_task)                             │
│    ┌─────────────────────────────────────────────────────────┐ │
│    │ a) 创建 StreamCallback 对象                              │ │
│    │    └─ 推送握手成功消息                                  │ │
│    │                                                          │ │
│    │ b) 调用 _execute_nl2sql_agent()                          │ │
│    │    └─ 创建 AgentContext                               │ │
│    │    └─ 实例化 NL2SQLAgent                               │ │
│    │    └─ 执行 agent.execute()                            │ │
│    │    └─ 处理结果格式（转换为 dict）                      │ │
│    │                                                          │ │
│    │ c) 推送完成或错误消息                                   │ │
│    └─────────────────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────────┐
│ 5. 结果处理阶段                                                   │
│    • 如果成功:                                                    │
│      ✓ 推送 task_completed 事件                                 │
│      ✓ 保存元数据到 Task.result_data                            │
│    • 如果失败:                                                    │
│      ✓ 推送 task_failed 事件                                    │
│      ✓ 保存错误信息到 Task.error_message                        │
└─────────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────────┐
│ 6. 持久化阶段 (_save_task_result_to_session)                   │
│    ✓ 从 Redis Stream 读取所有事件                               │
│    ✓ 解析并过滤有效的内容块                                      │
│    ✓ 执行去重逻辑（同一 content_id 只保存最新）                 │
│    ✓ 保存内容块到数据库会话                                      │
└─────────────────────────────────────────────────────────────────┘
```

### 异常处理路径

```
任务执行中抛出异常
        ↓
_execute_task_background() 的 except 块捕获
        ↓
推送 task_failed 事件
        ↓
调用 fail_task() 更新数据库
        ↓
后台任务结束（异常被记录但不传播）
```

## 关键组件

### 1. TaskService 类

**职责**: 统一的异步任务管理接口

#### 静态方法分类

**任务基础操作**

- `create_task()` - 创建新任务
- `get_task_by_id()` - 根 ID 获取任务
- `update_task_status()` - 更新任务状态
- `complete_task()` - 标记任务完成
- `fail_task()` - 标记任务失败

**任务执行**

- `submit_task()` - 异步提交任务（客户端调用）
- `_execute_task_background()` - 后台执行主流程
- `_execute_nl2sql_task()` - NL2SQL 任务执行
- `_execute_nl2sql_agent()` - Agent 调用

**流式输出**

- `generate_task_stream()` - 生成 SSE 流
- `_push_task_event()` - 推送事件到 Redis 和内存队列

**结果持久化**

- `_save_task_result_to_session()` - 从 Redis 读取并保存到数据库
- `_create_stream_callback()` - 创建流式回调对象
- `_parse_database_id()` - 安全解析 database_id
- `_initialize_task()` - 初始化任务

### 2. StreamCallback 对象

**用途**: 作为 Agent 和任务服务之间的通信通道

**使用方式**:

```python
# Agent 在执行过程中调用
await stream_callback(
    "内容文本",
    content_id="unique_id",
    content_type="text",
    title="标题",
    recall=False  # 该条信息是否回游
)
```

**推送路径**:

1. StreamCallback 内部验证内容
2. 包装成 event 对象
3. 推送到内存队列（实时）
4. 推送到 Redis Stream（持久化）

### 3. Redis Stream 事件结构

**事件格式**:

```json
{
  "type": "content_stream",
  "message_id": "1730704123000-a1b2c3d4",
  "content_id": "reasoning-001",
  "content_type": "text",
  "title": "问题分析",
  "content": "分析内容...",
  "session_id": "session-123",
  "user_id": 42,
  "recall": false
}
```

**事件类型**:

- `task_started` - 任务开始
- `processing_started` - 处理开始
- `content_stream` - 内容流（Agent 推送）
- `task_completed` - 任务完成
- `task_failed` - 任务失败
- `stream_error` - 流传输错误

## 数据流分析

### 请求到响应的完整数据流

```
1️⃣ 前端请求
   POST /api/sessions/chat
   Headers: Authorization: Bearer {token}
   Body: {
       "message": "某个查询",
       "session_id": "session-xxx",
       "database_id": 1  // 可选，用于覆盖session的database_id
   }
   ↓

2️⃣ 后端路由接收（backend/api/routes/session.py:283-358）
   @router.post("/chat")
   async def chat_with_session(request: ChatRequest, ...)
   ↓
   1. 验证 session 存在且可访问
   2. 保存用户消息到数据库
   3. 提交任务：await TaskService.submit_task(...)
   4. 返回 StreamingResponse SSE 流
   ↓
   3️⃣ 后端 TaskService 处理
   await TaskService.submit_task(
       db, session_id, user_id, user_message, database_id
   )
   ↓
   1. 创建 Task 记录到数据库，状态='pending'
   2. 立即返回 task_id → 前端响应头 X-Task-Id
   3. 启动后台任务: asyncio.create_task(_execute_task_background())
   ↓

3️⃣ 后台执行线程
   _execute_task_background(task_id)
   {
       task = await _initialize_task(db, task_id)
       session_context = await get_session_messages()

       agent_result = await _execute_nl2sql_task(...)

       if agent_result.error:
           await fail_task()
       else:
           await complete_task()

       await _save_task_result_to_session(db, task_id, session_id)
   }
   ↓

4️⃣ Agent 执行过程（在 _execute_nl2sql_task 内）
   stream_callback = _create_stream_callback(task_id, session_id, user_id)
   await nl2sql_agent.execute(agent_context, stream_callback=stream_callback)

   // Agent 内部调用，实时推送执行过程
   await stream_callback("分析用户查询...", content_type="text", title="问题分析")
   await stream_callback(generated_sql, content_type="sql")
   await stream_callback({"columns": [...], "rows": [...]}, content_type="table")
   ↓
   每次调用 stream_callback：
   a) 构造 event 对象（type='content_stream'）
   b) 推送到 Redis Stream → 持久化存储
   c) 推送到内存队列 → 在线用户立即收到
   ↓

5️⃣ 前端 SSE 连接（已在第 2 步自动建立）
   /*
   在步骤 2 中，/api/sessions/chat 的响应就是 StreamingResponse
   自动开始推送事件，前端不需要单独建立 SSE 连接
   */
   ↓
   return StreamingResponse(
       TaskService.generate_task_stream(...),
       media_type="text/event-stream"
   )
   ↓
   TaskService.generate_task_stream() 流程：
   ├─ 从内存队列读取已推送的事件（给在线用户）
   └─ 监控新推送的事件，逐条发送给前端
   ↓
   前端接收 SSE 事件
   data: {"type": "content_stream", "content": "...", ...}
   ↓

6️⃣ 结果持久化
   _save_task_result_to_session()
   {
       从 Redis Stream 读取所有事件
       过滤 session_id 匹配的事件
       提取 content_id, content_type, content
       执行去重（同 content_id 合并）
       保存 content_blocks 到 Message 表
   }
```

### 关键数据转换点

| 阶段       | 输入                      | 处理                         | 输出                 |
| ---------- | ------------------------- | ---------------------------- | -------------------- |
| 任务创建   | user_message, database_id | 包装成 input_data            | Task 记录            |
| 上下文准备 | session_id                | 查询历史消息                 | session_context list |
| Agent 执行 | AgentContext              | NL2SQLAgent.execute()        | Result 对象          |
| 结果转换   | Result 对象               | to_dict() 或手动构造         | Dict                 |
| 事件推送   | Dict 数据                 | JSON 序列化 + StreamCallback | Redis/内存队列       |
| 结果读取   | Redis Stream bytes        | JSON 反序列化                | event dict           |
| 内容提取   | event dict                | 字段解析 + 去重              | content_blocks list  |
| 持久化     | content_blocks list       | SessionService.add_message() | Message 记录         |

### StreamCallback 的作用

StreamCallback 是连接 Agent 执行和前端推送的关键桥梁。

**初始化**:

```python
def _create_stream_callback(task_id: str, session_id: str, user_id: int):
    callback = StreamCallback(
        task_id=task_id,
        session_id=session_id,
        user_id=user_id
    )
    return callback
```

**使用场景**:

| 场景         | 调用方式                                                                   | 用途                |
| ------------ | -------------------------------------------------------------------------- | ------------------- |
| 握手成功     | `await stream_callback("握手成功", title="握手成功", content_type="text")` | 通知前端连接建立    |

### 前端接收流程

**第一次连接**（初始请求）

```
POST /api/sessions/chat
    ↓
后端立即返回 StreamingResponse
    ↓
前端收到 SSE 事件流
    data: {"type": "task_started", ...}
    data: {"type": "processing_started", ...}
    data: {"type": "content_stream", ...}  // Agent 执行过程
    data: {"type": "task_completed", ...}
    data: [DONE]
```

**断线重连**（网络中断后恢复）

```
网络中断，SSE 连接断开
    ↓
前端保存 task_id（来自响应头 X-Task-Id）
    ↓
用户重新连接：POST /api/sessions/chat-continue
请求体：{
    "session_id": "session-xxx",
    "task_id": "task-yyy"
}
    ↓
后端验证：
├─ task 存在且属于该 session
├─ 检查任务状态
    ├─ 已完成(completed/failed/cancelled): 发送历史消息后结束
    └─ 运行中(pending/running): 发送历史消息后继续监控
    ↓
返回 StreamingResponse
    ↓
前端按照新 SSE 流接收
    ├─ 首先接收之前的历史事件（从 Redis Stream 读取）
    └─ 然后接收新推送的事件
```

**关键特点**:

- Redis Stream 提供了完整的事件历史，支持从任意消息 ID 开始读取
- 前端断线时不会丢失已推送的内容
- 使用 `is_new_connection` 标志区分新连接和重连

**前端实现参考** (webui/src/api/session.js):

```javascript
// 第一次请求
const response = await sendMessageToSession(sessionId, message, {
  database_id: 1,
});

// 断线重连
const response = await continueSessionStream(sessionId, taskId);

// 两个函数都返回 fetch Response 对象，支持 EventSource 式的流处理
```

**后端响应详解**:

1. **第一次连接** (`/api/sessions/chat`)

   - 返回 `StreamingResponse`
   - 响应头包含 `X-Task-Id: {task_id}`
   - 前端需要保存此 task_id 用于重连

2. **断线重连** (`/api/sessions/chat-continue`)
   - 请求体包含 session_id 和 task_id
   - 后端验证 task 属于该 session
   - 根据任务状态返回历史 + 新事件，或仅返回历史

## 错误处理

### 三层异常处理机制

**第 1 层 - Agent 执行异常** (`_execute_nl2sql_agent`)

```python
try:
    agent_result = await nl2sql_agent.execute(...)
except Exception as agent_error:
    logger.error(f"Agent执行异常: {agent_error}")
    if stream_callback:
        await stream_callback(f"执行过程中发生错误：{str(agent_error)}",
                             content_type="error")
    return {"error": str(agent_error)}
```

**第 2 层 - 任务执行异常** (`_execute_task_background`)

```python
try:
    agent_result = await _execute_nl2sql_task(...)
    if agent_result.get('error'):
        await fail_task(db, task_id, agent_result.get('error'))
    else:
        await complete_task(db, task_id, result_metadata)
except Exception as e:
    logger.error(f"Async task {task_id} failed: {e}")
    await _push_task_event(task_id, 'task_failed', {...})
    await fail_task(db, task_id, str(e))
```

**第 3 层 - 流输出异常** (`generate_task_stream`)

```python
async def generate_task_stream(...) -> AsyncGenerator[str, None]:
    try:
        async for sse_message in streaming_manager.generate_task_stream(...):
            yield sse_message
    except Exception as e:
        logger.error(f"SSE stream error: {e}")
        error_event = {
            'type': 'stream_error',
            'message': f'流式传输错误: {str(e)}'
        }
        yield f"data: {json.dumps(error_event)}\n\n"
```

### 数据库异常处理

**场景 1 - Task 不存在**

```python
task = await get_task_by_id(db, task_id)
if not task:
    raise ValueError(f"Task {task_id} not found")
```

**场景 2 - Redis 写入失败**

```python
try:
    await redis_manager.add_to_stream(stream_key, message_data)
except Exception as e:
    logger.error(f"Failed to push task event for {task_id}: {e}")

```

**场景 3 - 结果序列化失败**

```python
from core.utils.serialization import SerializationManager
cleaned_data = SerializationManager.serialize(result_data)
await db.execute(
    update(Task).where(Task.id == task_id)
    .values(status='completed', result_data=cleaned_data)
)
```

## Redis Stream 集成

### Redis Stream 的作用

Redis Stream 是持久化事件队列，解决两个核心问题：

1. **断线重连恢复**: 用户刷新页面或网络中断后，可以从 Redis 读取已推送的事件
2. **事件持久化**: 所有重要事件都被记录，不会丢失

### 事件推送流程

```
_push_task_event()
    ↓
    ┌─ 生成唯一 message_id："{timestamp}-{uuid}"
    │
    ├─ 构造 message 对象（根据 event_type 决定结构）
    │
    ├─ 获取 Redis Stream Key：f"task_stream:{task_id}"
    │
    ├─ 构造 message_data（包含 message_id、data、timestamp）
    │
    ├─ 推送到 Redis Stream
    │  redis_manager.add_to_stream(stream_key, message_data)
    │
    └─ 推送到内存队列（如果失败只记录警告）
       memory_event_queue.put_event(task_id, event_type, data)
```

### 事件读取流程（持久化阶段）

```
_save_task_result_to_session()
    ↓
    1. 读取 Stream：redis_manager.read_stream_from_id(stream_key, '0', count=1000)
    │  返回结构：[(stream_key, [(msg_id, msg_data), ...])]
    │
    ├─ 解析嵌套结构
    │
    ├─ 对每条消息：
    │  a) 解析 JSON（如果是字符串）
    │  b) 验证 session_id 匹配（跨会话数据分离）
    │  c) 提取 content_id、content_type、content
    │
    ├─ 执行去重逻辑：
    │  ├─ 新内容：添加到 content_blocks
    │  └─ 已存在 content_id：
    │      ├─ table 类型：替换（最新覆盖）
    │      └─ 文本类型：累积追加
    │
    └─ 保存 content_blocks 到数据库
       SessionService.add_message(..., content_items=content_blocks)
```

### 数据验证和清理

**session_id 验证**

```python
event_session_id = actual_data.get('session_id')
if event_session_id != session_id:
    continue  # 跳过不匹配的事件
```

**内容完整性检查**

```python
content_id = actual_data.get('content_id')
content_type = actual_data.get('content_type')
content = actual_data.get('content')

if not (content_id and content_type and content):
    continue  # 跳过不完整的内容
```

**去重机制**

```python
seen_content_ids = set()  # 追踪已见过的 content_id

if content_id in seen_content_ids:
    # 更新已存在的块
    for block in content_blocks:
        if block['id'] == content_id:
            if content_type == 'table' and isinstance(content, dict):
                block['content'] = content  # 替换
            elif isinstance(block['content'], str) and isinstance(content, str):
                block['content'] += content  # 追加
else:
    # 新块
    seen_content_ids.add(content_id)
    content_blocks.append({...})
```

## 实现细节

### 1. 任务创建 (create_task)

```python
async def create_task(db, session_id, user_id, user_message, input_data=None):
    # 1. 合并 user_message 到 input_data
    task_input_data = input_data or {}
    task_input_data['user_message'] = user_message

    # 2. 创建 Task 对象
    task = Task(
        session_id=session_id,
        user_id=user_id,
        task_type='sql_generation',
        input_data=task_input_data,
        status='pending'
    )

    # 3. 保存到数据库
    db.add(task)
    await db.commit()
    await db.refresh(task)

    return task
```

**特点**:

- `input_data` 包含了所有初始数据（user_message、database_id）
- Task 初始状态为 'pending'
- 立即提交到数据库（不需要等待后台执行）

### 2. 异步提交 (submit_task)

**调用路径**:

```
前端 POST /api/sessions/chat
    ↓
route: chat_with_session() (session.py:283-358)
    ├─ 验证 session
    ├─ 保存用户消息到数据库
    └─ 调用 TaskService.submit_task()
```

**实现代码**:

```python
async def submit_task(db, session_id, user_id, user_message, database_id):
    # 1. 创建 Task 记录
    task = await TaskService.create_task(
        db=db,
        session_id=session_id,
        user_id=user_id,
        user_message=user_message,
        input_data={'database_id': database_id}
    )

    # 2. 立即启动后台任务
    asyncio.create_task(TaskService._execute_task_background(task.id))

    # 3. 立即返回 task_id（不阻塞）
    return task.id
```

**设计特点** (Linus 重构):

- 使用 `asyncio.create_task()` 而不是 `asyncio.run()`
- 立即返回 task_id，不等待执行完成
- 后台任务自己处理数据库连接和异常
- task_id 通过 SSE 响应头 `X-Task-Id` 返回给前端

### 3. 后台执行主流程 (\_execute_task_background)

```python
async def _execute_task_background(task_id: str):
    from config import async_session_factory

    session_id = None
    user_id = None

    try:
        async with async_session_factory() as db:
            # 1. 初始化任务
            task = await TaskService._initialize_task(db, task_id)
            session_id = task.session_id
            user_id = task.user_id

            # 2. 获取会话历史
            session_context = await SessionService.get_session_messages(
                db, session_id, task.user_id, role="user"
            )

            # 3. 解析输入数据
            user_message = task.get_user_message()
            database_id = TaskService._parse_database_id(task.input_data)

            # 4. 推送处理开始事件
            await TaskService._push_task_event(
                task_id, 'processing_started', {
                    'user_message': user_message,
                    'database_id': database_id
                }
            )

            # 5. 执行 NL2SQL 任务
            agent_result = await TaskService._execute_nl2sql_task(
                task_id=task_id,
                user_message=user_message,
                database_id=database_id,
                session_context=session_context or [],
                user_id=task.user_id,
                session_id=session_id
            )

            # 6. 处理结果
            if isinstance(agent_result, dict) and agent_result.get('error'):
                await TaskService.fail_task(db, task_id, agent_result.get('error'))
            else:
                await TaskService.complete_task(db, task_id, {
                    'task_id': task_id,
                    'status': 'completed',
                    'timestamp': datetime.now().isoformat()
                })

            # 7. 保存结果到会话
            await TaskService._save_task_result_to_session(db, task_id, session_id)

    except Exception as e:
        logger.error(f"Async task {task_id} failed: {e}")
        # 异常处理：推送失败事件、更新状态
        await TaskService._push_task_event(task_id, 'task_failed', {...})
        async with async_session_factory() as db:
            await TaskService.fail_task(db, task_id, str(e))
```

**执行顺序关键**:

1. 初始化任务（推送 task_started）
2. 获取上下文
3. 推送处理开始信号
4. 执行 Agent
5. 推送完成/失败信号
6. 持久化结果到会话

### 4. Agent 执行 (\_execute_nl2sql_agent)

```python
async def _execute_nl2sql_agent(
    task_id, user_message, database_id, session_context, user_id, stream_callback
):
    try:
        # 1. 创建 Agent 上下文
        agent_context = AgentContext(
            task_id=task_id,
            user_id=user_id,
            input_data={
                "user_message": user_message,
                "database_id": database_id,
                "session_context": session_context
            }
        )

        # 2. 创建 NL2SQL Agent
        nl2sql_agent = NL2SQLAgent()

        # 3. 执行 Agent
        agent_result = await nl2sql_agent.execute(agent_context, stream_callback=stream_callback)

        # 4. 转换结果为 dict
        if agent_result and hasattr(agent_result, 'to_dict'):
            result_dict = agent_result.to_dict()
        else:
            result_dict = {
                "success": agent_result.success if agent_result else False,
                "data": getattr(agent_result, 'data', {}),
                "error": getattr(agent_result, 'error', None)
            }

        # 5. 推送完成信息
        if stream_callback:
            if not result_dict.get("success"):
                error_msg = result_dict.get("error", "未知错误")
                await stream_callback(f"查询处理失败：{error_msg}", status="end")

        # 6. 返回结果
        if result_dict.get("success"):
            return result_dict
        else:
            raise Exception(f"Agent执行失败: {result_dict.get('error')}")

    except Exception as e:
        logger.error(f"Agent执行异常: {e}")
        return {"error": str(e)}
```

**关键点**:

- 创建单一 AgentContext 实例，传递给 Agent
- 所有 Agent 执行的流式输出都通过 `stream_callback` 进行
- 结果必须转换为 dict（避免序列化问题）
- 异常被捕获并转换为 `{"error": ...}` 格式

### 5. 内容保存 (\_save_task_result_to_session)

这是最复杂的方法，涉及 Redis 读取、数据验证、去重和数据库保存。

**核心算法**:

```
1. 从 Redis Stream 读取所有事件
   └─ 返回: [(stream_key, [(msg_id, msg_data), ...])]

2. 迭代消息列表
   ├─ 解析 JSON（处理嵌套 data 字段）
   ├─ 验证 session_id 匹配
   ├─ 提取 content_id、content_type、content
   └─ 执行完整性检查

3. 去重处理
   ├─ 首次见到的 content_id：添加到 content_blocks
   └─ 已存在的 content_id：
       ├─ table 类型：替换为最新版本
       └─ text 类型：文本累积追加

4. 保存到数据库
   └─ 调用 SessionService.add_message()
       ├─ role='assistant'
       ├─ content_items=content_blocks
       └─ metadata={'source': 'redis_stream', ...}
```

**去重示例**:

```python
# 第一次推送：sql-001，内容="SELECT * FROM users"
# 第二次推送：sql-001，内容="SELECT id, name FROM users"
# 结果：sql-001 的内容被替换为第二次推送的版本（最新覆盖）

# 第一次推送：reasoning-001，内容="思考第1步"
# 第二次推送：reasoning-001，内容=" → 思考第2步"
# 结果：reasoning-001 的内容="思考第1步 → 思考第2步"（文本累积）
```

## 总结

TaskService 是 YiW 任务管理的核心，设计特点：

✅ **异步非阻塞** - 立即响应，后台执行
✅ **双推送机制** - Redis（持久化） + 内存队列（实时）
✅ **完整生命周期** - pending → running → completed/failed
✅ **流式输出** - Agent 逐步推送执行过程
✅ **断线恢复** - Redis Stream 支持事件重放
✅ **数据持久化** - 所有结果保存到数据库会话
✅ **错误容错** - 三层异常处理机制

这种设计使得系统可以处理长时任务，同时保证了用户体验（实时反馈）和数据可靠性（持久化）。
