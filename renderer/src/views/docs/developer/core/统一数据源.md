## 背景问题

在原有架构中，我们需要处理三种不同类型的数据源：
- **数据库连接** (DatabaseConnection) - 完整的schema，支持SQL查询
- **结构化数据** (CSV/Excel文件) - 文件元数据，包含表头和采样值
- **非结构化数据** (文本文档) - 向量数据库管理的文档内容

### 业务需求

1. **多租户隔离** - 每个用户只能访问自己的业务和数据源
2. **统一接口** - PlanAgent需要统一的方式来访问不同类型的数据源
3. **智能召回** - 根据用户问题智能剪枝和选择相关数据源
4. **业务级管理** - 一个业务可以绑定多个不同类型的数据源

## StorageBackend的问题

### 1. 命名不准确

StorageBackend这个名字具有误导性：
```python
class StorageBackend(ABC):
    @abstractmethod
    async def explore(self) -> dict[str, Iterable[str]]:  # 探索数据库和表
    @abstractmethod
    async def profile(self, database: str, table: str) -> Profile:  # 获取表profile
    @abstractmethod
    def load(self, database: str, table: str) -> pd.DataFrame:  # 加载数据
    @abstractmethod
    async def kb_explore(self) -> list[str]:  # 探索知识库
    @abstractmethod
    async def kb_search(self, query: str) -> Any:  # 知识库搜索
```

**问题**：这个"StorageBackend"实际上是一个混合的数据处理器，既处理结构化数据（表、列），又处理非结构化数据（知识库），职责混乱。

### 2. 职责过于复杂

StorageBackend承担了至少三种不同的职责：
- **数据加载** - `load()` 方法处理文件和数据库数据
- **元数据管理** - `profile()` 和 `explore()` 处理schema信息
- **知识库搜索** - `kb_search()` 和 `kb_explore()` 处理文本搜索

**评价**："这是在用一个接口解决所有问题，违反了单一职责原则。"

### 3. 缺乏业务上下文

StorageAgent需要手动管理多个Backend实例：
```python
class StorageAgent(BaseAgent):
    def __init__(self, static_backends: list[StorageBackend], intermediate_backend: IntermediateStorageBackend):
        self.managed_backends = static_backends + [intermediate_backend]
        self.db_to_backend: dict[str, StorageBackend] = {}
        self.kb_to_backend = {}
```

**问题**：
- 需要手动维护`db_to_backend`映射
- 缺乏业务级的数据隔离
- 无法知道数据源属于哪个业务


## BusinessDataSources设计思路

### 1. 核心设计原则

遵循Linus的"好品味"原则：
- **消除特殊情况** - 统一的数据源接口
- **数据结构驱动** - 以数据源为核心抽象
- **职责单一** - 每个组件都有明确的职责

### 2. 统一数据源抽象

```python
class DataSource(ABC):
    def __init__(self, id: int, business_id: int, user_id: int, source_type: str):
        self.id = id
        self.business_id = business_id
        self.user_id = user_id
        self.source_type = source_type

    @abstractmethod
    async def get_schema(self, user_message: Optional[str] = None) -> Dict[str, Any]:
        """获取schema，支持智能剪枝"""
        pass

    @abstractmethod
    async def query(self, query: str) -> Any:
        """查询数据源"""
        pass
```

**优势**：
- 统一的接口设计
- 携带完整的上下文信息（business_id, user_id）
- 支持智能召回（通过user_message参数）

### 3. 三种数据源实现

```python
# 数据库数据源
class DatabaseDataSource(DataSource):
    async def get_schema(self, user_message: Optional[str] = None) -> Dict[str, Any]:
        if user_message:
            # 使用SchemaRetrievalService进行智能召回
            return await SchemaRetrievalService.search_relevant_tables_with_columns(...)
        else:
            # 返回完整schema
            return await self._get_full_schema()

# 结构化数据源
class StructuredDataSource(DataSource):
    async def get_schema(self, user_message: Optional[str] = None) -> Dict[str, Any]:
        # 基于StructuredTable和StructuredColumn模型
        return {
            "tables": [{"table_name": str, "columns": [...]}]
        }

# 非结构化数据源
class UnstructuredDataSource(DataSource):
    async def get_schema(self, user_message: Optional[str] = None) -> Dict[str, Any]:
        # 基于UnstructuredDocument模型
        return {
            "documents": [{"title": str, "file_path": str, "description": str}]
        }
```

### 4. 业务级容器

```python
class BusinessDataSources:
    def __init__(self, business_id: int, user_id: int):
        self.business_id = business_id
        self.user_id = user_id
        self.data_sources: Dict[int, DataSource] = {}

    async def load_sources(self):
        # 使用BusinessService获取数据源信息
        data_sources_info = await BusinessService.get_data_sources(db, self.business_id, self.user_id)

        # 创建DataSource实例
        for db_info in data_sources_info["database_connections"]:
            data_source = DatabaseDataSource(self.business_id, self.user_id, db_info["id"])
            self.data_sources[data_source.id] = data_source

    def get_data_source(self, source_id: int) -> Optional[DataSource]:
        return self.data_sources.get(source_id)
```

## 架构对比

### StorageBackend架构

```
StorageAgent
  ├── DatabaseBackend (处理SQL数据库)
  ├── FileSystemBackend (处理文件)
  └── IntermediateBackend (处理中间结果)
     ↓
  手动维护 db_to_backend 映射
  手动管理多个Backend实例
  缺乏业务上下文
```

**问题**：
- 需要手动映射管理
- 缺乏业务级隔离
- 职责混乱

### BusinessDataSources架构

```
BusinessDataSources(business_id, user_id)
  ├── DatabaseDataSource (connection_id)
  ├── StructuredDataSource (structured_data_source_id)
  └── UnstructuredDataSource (unstructured_data_source_id)
     ↓
  统一的DataSource接口
  自动权限验证
  完整的业务上下文
  智能召回支持
```

**优势**：
- 自动管理数据源
- 统一的访问接口
- 完整的业务上下文
- 支持智能召回

## BusinessDataSources使用指南

### 1. 基本使用

```python
# 在TaskService中的使用
async def submit_task(db, session_id, user_id, user_message, business_id):
    # 创建业务数据源容器
    business_data_sources = BusinessDataSources(business_id, user_id)

    # 加载该业务的所有数据源（包含权限验证）
    await business_data_sources.load_sources()

    # 获取所有数据源
    all_sources = business_data_sources.get_all_sources()

    # 传递给Agent
    agent_context = AgentContext(
        task_id=task_id,
        user_id=user_id,
        input_data={
            "user_message": user_message,
            "business_data_sources": business_data_sources
        }
    )
```

### 3. 在PlanAgent中使用

```python
class PlanAgent(BaseAgent):
    async def reasoning(self, context, stream_callback, **kwargs):
        agent_context: AgentContext = kwargs["agent_context"]
        business_data_sources = agent_context.input_data["business_data_sources"]

        # 获取所有schema（带智能剪枝）
        question = agent_context.input_data["user_message"]
        schemas = await business_data_sources.get_all_schemas(user_message=question)

        # 生成查询计划
        plan = await self._generate_plan(question, schemas)

        # 执行计划
        result = await self._execute_plan(plan, business_data_sources)
```

## 最佳实践

### 1. 数据源创建

```python
# ✅ 正确：在TaskService中创建
business_data_sources = BusinessDataSources(business_id, user_id)
await business_data_sources.load_sources()

# ❌ 错误：手动创建DataSource
# 应该通过BusinessDataSources统一管理，避免手动创建
```

### 2. Schema获取

```python
# ✅ 正确：使用智能剪枝
source = business_data_sources.get_data_source(source_id)
schema = await source.get_schema(user_message="查询销售数据")

# ✅ 也正确：获取完整schema
full_schema = await source.get_schema()
```

### 3. 错误处理

```python
# ✅ 正确：检查数据源是否存在
source = business_data_sources.get_data_source(source_id)
if not source:
    raise ValueError(f"数据源 {source_id} 不存在")

# ✅ 正确：处理schema获取失败
try:
    schema = await source.get_schema()
except Exception as e:
    logger.error(f"获取schema失败: {e}")
    return {"tables": [], "error": str(e)}
```

### 4. 性能优化

```python
# ✅ 正确：复用BusinessDataSources实例
business_data_sources = BusinessDataSources(business_id, user_id)
await business_data_sources.load_sources()

# 多次使用同一个实例，避免重复加载
schema1 = await business_data_sources.get_data_source(1).get_schema("查询1")
schema2 = await business_data_sources.get_data_source(2).get_schema("查询2")
```

## 总结

### BusinessDataSources的核心价值

1. **统一抽象** - 消除了StorageBackend的职责混乱
2. **业务完整性** - 提供业务级的数据源管理
3. **权限安全** - 自动处理用户权限验证
4. **智能召回** - 支持基于用户问题的schema剪枝
5. **动态管理** - 支持运行时数据源的增删操作（仅内存）
6. **扩展性强** - 易于添加新的数据源类型

### 与StorageBackend的对比

| 特性 | StorageBackend | BusinessDataSources |
|------|----------------|-------------------|
| 职责 | 混乱（数据+元数据+搜索） | 清晰（统一数据源抽象）|
| 业务上下文 | ❌ 缺乏 | ✅ 完整 |
| 权限管理 | ❌ 手动处理 | ✅ 自动验证 |
| 智能召回 | ❌ 不支持 | ✅ 原生支持 |
| 动态管理 | ❌ 不支持 | ✅ 内存级增删 |
| 多租户 | ❌ 不支持 | ✅ 原生支持 |
| 扩展性 | ❌ 困难 | ✅ 容易 |

BusinessDataSources架构遵循了"好的品味"原则：**消除特殊情况，统一数据结构，让代码变得简单而可维护**。
