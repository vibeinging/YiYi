# 核心概念

在开始配置或使用 YiW 之前，建议先了解几个关键概念。理解这些概念有助于你判断某项功能应该由谁配置、在什么位置配置，以及它会如何影响后续查询结果。

## 项目（Project）

项目是 YiW 中组织工作的基本单元，可以理解为一个独立的工作空间。

在项目内管理的内容通常包括：

- 数据源
- 业务语义配置
- 模型配置
- Dashboard
- 项目成员与角色

### 为什么需要项目

- 项目用于隔离不同业务范围的数据和配置。
- 项目用于区分不同团队成员及其权限范围。
- 项目用于集中管理模型、数据源和可视化结果。

如果你的团队同时维护多个业务域、多个客户环境或多个部门数据，通常应分别建立独立项目。

## 成员与角色（Members & Roles）

项目中的每个成员都通过角色获得权限。角色决定该成员是否可以查看某些页面，以及是否可以执行配置、修改或删除等操作。

### 常见角色

系统通常提供以下预置角色：

| 角色 | 说明 | 典型用户 |
|-----|-----|---------|
| **项目管理员** | 拥有项目的所有权限 | 项目负责人、技术经理 |
| **数据管理员** | 管理数据源和业务配置 | 数据工程师、DBA |
| **数据分析师** | 使用Agent 工作区提问功能 | 业务分析师、运营人员 |
| **报表管理员** | 创建和管理 Dashboard | BI 工程师、报表专员 |

### 核心权限

| 权限 | 说明 |
|-----|-----|
| `ask_data` | 使用Agent 工作区提问、查看Agent 对话列表 |
| `data_manage` | 管理数据库、业务配置和数据源 |
| `model_service_manage` | 管理对话模型和嵌入模型 |
| `report_manage` | 创建和管理 Dashboard |
| `member_manage` | 邀请成员、管理成员角色 |
| `project_admin` | 项目设置、删除项目 |

如果你只能进行提问而无法配置模型或数据源，通常是因为当前角色未被授予相应权限。

## 业务（Business）

业务配置用于描述数据的业务含义，帮助系统理解你的问题与底层数据之间的对应关系。

### 为什么需要业务配置

数据库中的表名和字段名往往采用技术命名，例如 `usr_nm`、`ord_amt`。如果缺少业务说明，系统可能无法准确判断这些字段在业务中的真实含义。

通过业务配置，可以将技术名称与业务语言建立对应关系，例如：

- 将 `usr_nm` 映射为「用户姓名」
- 将 `ord_amt` 映射为「订单金额」
- 定义「销售额」的计算公式

### 业务配置的主要组成

| 组件 | 作用 | 示例 |
|-----|-----|-----|
| **标准名词** | 定义业务术语和字段映射 | `usr_nm` → 用户姓名 |
| **业务指标** | 预定义关键指标的计算规则 | 「日活用户数」= COUNT(DISTINCT user_id) |
| **样例数据** | 提供问答示例帮助 AI 学习 | "上周销售额是多少" → SELECT... |

### 何时应该补充业务配置

- 系统能够连接数据库，但查询结果不准确。
- 表名和字段名较为抽象，不符合业务人员日常表述。
- 团队内部对关键指标已有统一口径，需要在系统内固化。
- 常见问题反复出现，希望系统更稳定地理解相同语义。

## 数据源（Data Source）

数据源是项目中的数据入口。只有完成数据接入后，系统才能基于这些数据回答问题或构建 Dashboard。

### 数据源类型

| 类型 | 支持格式 | 使用场景 |
|-----|---------|---------|
| **数据库** | MySQL, PostgreSQL, Oracle, SQL Server, SQLite | 结构化数据查询 |
| **非结构化数据源** | PDF, Word, TXT, Markdown | 文档问答 |
| **结构化数据源** | API 接口, CSV, Excel | 外部数据集成 |
| **网络数据源** | 搜索引擎 | 实时获取互联网信息 |

### 一般配置顺序

1. **添加数据源**：配置连接信息
2. **同步元数据**：获取表结构信息
3. **配置业务**：添加业务名称和说明
4. **测试查询**：验证配置是否正确

## 智能对话

YiW 提供多种对话模式，以适配不同分析任务。

### 智能问数

适用于日常数据查询和统计分析。用户用自然语言描述问题，系统根据已配置的数据和语义返回结果。

| 查询类型 | 示例 |
|---------|-----|
| 简单查询 | "查询所有用户" |
| 聚合统计 | "上个月的总销售额是多少" |
| 条件筛选 | "VIP 用户有多少" |
| 分组对比 | "各部门的人数对比" |
| 趋势分析 | "最近7天的订单趋势" |

### 归因分析

适用于分析指标变化原因，例如某项指标为什么上涨、下降或明显偏离预期。

适用场景：
- 分析业绩波动原因（如「为什么本月销售额下降」）
- 找出优势/劣势因素（如「西安分行为什么业绩最好」）
- 异常数据归因（如「哪些因素导致了退货率上升」）

### 深度研究

适用于需要从外部资料中收集信息并形成较完整研究结果的场景。

适用场景：
- 学术文献调研（如「深度学习在医学影像中的应用」）
- 技术方案研究（如「分布式数据库的一致性算法」）

### 数据科学

适用于较复杂的数据分析任务，例如预测、建模或统计检验。

适用场景：
- 预测分析（如「预测下季度销售趋势」）
- 聚类分析（如「对客户进行分群」）
- 统计检验（如「A/B 测试结果是否显著」）

## Dashboard

Dashboard 用于展示和共享查询结果，是项目中的可视化页面。

### 相关概念

| 概念 | 说明 |
|-----|-----|
| **Dashboard** | 数据看板，包含多个数据面板 |
| **数据面板** | 单个可视化结果区域（图表、表格等） |
| **已保存结果** | 可复用的查询结果内容 |

### 常见使用流程

1. 在对话中执行查询
2. 将查询结果保存为可复用结果
3. 创建 Dashboard
4. 将结果添加到 Dashboard
5. 调整布局并保存
