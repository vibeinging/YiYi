# 成员管理

成员管理用于控制谁可以进入项目，以及每位成员在项目中拥有哪些操作权限。它是项目协作管理的核心页面之一。

> **权限要求**：需要 `member_manage`（成员管理）权限
>
> **谁有这个权限**：项目管理员、或被授予成员管理权限的角色

## 进入成员管理页面

**操作路径**：`侧边栏` → `项目设置` → `成员管理`

## 可以在成员管理中做什么

常见操作包括：

- 邀请新成员加入项目
- 查看当前项目成员
- 调整成员角色
- 移除不再需要访问项目的成员

## 邀请成员

### 邀请前建议确认

邀请成员前，建议先明确以下事项：

- 对方是否确实需要访问该项目
- 应分配哪个角色
- 是否只需要查询权限，还是需要管理权限

### 邀请方式

可通过项目中的邀请方式将成员加入项目。

邀请完成后，建议提醒对方：

- 使用正确账号登录
- 通过邀请入口进入项目
- 首次进入后确认自己看到的菜单是否与角色相符

## 查看成员列表

在成员列表中，通常可以查看：

- 成员名称或账号
- 当前角色
- 加入时间
- 邀请或使用状态

这些字段用于帮助管理员掌握当前项目的访问范围和角色分布。

## 修改成员角色

当成员职责发生变化时，可调整其角色。例如：

- 从仅查询数据调整为可管理报表
- 从普通成员调整为数据管理员
- 收缩原本过大的权限范围

角色修改后，成员可见菜单和可执行操作也会随之变化。

## 移除成员

如果某位成员不再需要访问项目，可将其移除。

移除前建议确认：

- 该成员当前是否仍负责项目中的某项工作
- 是否仍有需要保留交接的内容
- 是否已将相关职责转交给其他成员

移除后，该成员将无法继续访问该项目中的资源。

## 权限管理建议

- 尽量按职责分配角色，而不是按个人习惯随意放大权限。
- 对只需要查看结果的成员，优先分配最小必要权限。
- 对拥有管理权限的成员，建议定期复核其角色是否仍然合理。

## 注意事项

- 成员数量变化后，建议同步检查角色分布是否合理。
- 邀请完成后，如成员无法看到预期页面，优先检查角色是否分配正确。
- 对长期不再使用项目的成员，应及时移除访问权限。
