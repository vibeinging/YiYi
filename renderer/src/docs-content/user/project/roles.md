# 角色与权限

角色与权限用于控制项目成员可以查看哪些页面，以及可以执行哪些操作。合理的角色设计有助于在保证协作效率的同时，避免不必要的权限扩大。

> **权限要求**：需要 `member_manage`（成员管理）权限
>
> **谁有这个权限**：项目管理员、或被授予成员管理权限的角色

## 进入角色管理页面

**操作路径**：`侧边栏` → `项目设置` → `角色管理`

## 核心权限

项目中常见的核心权限包括：

| 权限代码 | 权限名称 | 说明 |
|----------|----------|------|
| `ask_data` | 数据查询 | 发起Agent 工作区提问、查看Agent 对话列表 |
| `data_manage` | 数据管理 | 管理数据库、业务配置和数据源 |
| `model_service_manage` | 模型管理 | 管理对话模型和嵌入模型 |
| `report_manage` | 报表管理 | 创建和管理 Dashboard |
| `member_manage` | 成员管理 | 邀请成员、调整角色、移除成员 |
| `project_admin` | 项目管理 | 管理项目级配置和关键设置 |

## 预置角色示例

系统一般会提供若干预置角色，以下为常见示例：

### 项目管理员

适合项目负责人或需要全面管理项目的成员，通常拥有完整权限。

### 数据管理员

适合负责数据接入、业务配置和日常维护的成员。

### 数据分析师

适合以查询和分析为主的成员，通常侧重使用数据，不负责系统配置。

### 报表管理员

适合负责整理和维护 Dashboard 的成员。

## 角色与权限关系示例

以下表格用于帮助理解常见角色的大致权限范围：

| 角色 | 查询数据 | 数据管理 | 模型管理 | 报表管理 | 成员管理 | 项目管理 |
|------|----------|----------|----------|----------|----------|----------|
| 项目管理员 | 有 | 有 | 有 | 有 | 有 | 有 |
| 数据管理员 | 有 | 有 | 可按需要授予 | 可按需要授予 | 一般不授予 | 一般不授予 |
| 数据分析师 | 有 | 无 | 无 | 无或较少 | 无 | 无 |
| 报表管理员 | 有 | 无 | 无 | 有 | 无 | 无 |

实际角色定义应以当前项目采用的权限方案为准。

## 什么时候需要自定义角色

当预置角色无法满足团队职责划分时，可以考虑创建自定义角色。例如：

- 仅允许管理模型，但不能管理成员
- 允许维护 Dashboard，但不能修改数据源
- 允许查询和查看Agent 对话列表，但不能进行其他配置

## 设计角色时的建议

- 按岗位职责设计角色，而不是按个人习惯设计角色。
- 优先从现有预置角色出发，只有在确有必要时才新增自定义角色。
- 对同一类成员尽量使用统一角色，避免项目内权限结构过于复杂。
- 对高权限角色应定期复核。

## 权限变更后会影响什么

当成员角色发生变化时，通常会影响：

- 可见菜单
- 可进入页面
- 可执行的新增、编辑、删除操作

如果成员反馈“看不到某个页面”或“突然无法操作”，优先检查其当前角色和权限是否发生变化。

## 注意事项

- 权限应遵循最小必要原则。
- 高权限角色不宜分配过多。
- 对共享项目，建议在角色名称和职责说明上保持清晰一致。
