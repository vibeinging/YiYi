# 模型管理

模型管理用于配置项目可使用的对话模型和嵌入模型。模型配置是否正确，会直接影响Agent 工作区提问、文档检索和语义召回等功能是否可用。

> **权限要求**：需要 `model_service_manage`（模型管理）权限
>
> **谁有这个权限**：项目管理员、或被分配了「模型管理」权限的角色

## 进入模型管理页面

**操作路径**：`侧边栏` → `模型配置` → `模型管理`

## 使用前准备

开始配置前，建议先确认以下事项：

- 你已获得目标模型服务的访问地址和认证信息。
- 你知道应使用的模型名称或部署名称。
- 你清楚当前项目需要的是对话模型、嵌入模型，还是两者都需要。

如果项目只使用数据库进行基础Agent 工作区提问，至少需要先配置一个对话模型。若项目还需要文档检索、语义召回或向量化能力，则通常还需要配置嵌入模型。

## 模型类型

### 对话模型

对话模型主要用于：

- 理解用户问题
- 辅助生成查询或分析结果
- 生成结果说明

### 嵌入模型

嵌入模型主要用于：

- 文档向量化
- 文本相似度计算
- 语义召回和检索

## 配置对话模型

1. 进入模型管理页面。
2. 切换到对话模型区域。
3. 新建模型配置。
4. 填写模型名称、服务商、模型标识、接口地址和 API 密钥等信息。
5. 执行连接测试。
6. 测试通过后保存配置。
7. 将该模型设为激活状态。

### 常见配置项

| 配置项 | 说明 |
|--------|------|
| 模型名称 | 页面中的显示名称，便于区分不同模型 |
| 服务商 | 模型服务提供方 |
| 模型标识 | 实际调用的模型名称或部署名称 |
| API 地址 | 模型服务接口地址 |
| API 密钥 | 认证密钥 |
| 额外参数 | 视服务商要求填写的补充参数 |

## 配置嵌入模型

1. 切换到嵌入模型区域。
2. 新建模型配置。
3. 填写模型名称、服务商、模型标识、接口地址、API 密钥等信息。
4. 根据需要填写向量维度等补充参数。
5. 执行连接测试。
6. 测试通过后保存，并将目标模型设为激活状态。

## 如何判断配置是否成功

模型配置完成后，建议至少确认以下几点：

- 连接测试通过。
- 目标模型已处于激活状态。
- 对话模型可用于发起查询。
- 嵌入模型可被相关数据源正常选择和使用。

如果模型已保存但相关页面仍无法使用，通常需要进一步检查权限、接口地址、模型名称和密钥配置是否一致。

## 激活、编辑与删除

1. 在模型列表中找到目标模型
2. 根据需要执行激活、编辑或删除操作

### 激活

同一类型通常只能有一个激活模型。激活新模型后，原来的激活模型会被替换。

### 编辑

当模型地址、密钥或模型名称变化时，应及时更新配置并重新测试。

### 删除

如果某个模型不再使用，可以删除；但在删除前，建议先确认当前项目是否已有其他可用模型替代。

## 常见问题

### 测试失败时应先检查什么

- API 地址是否正确
- 模型标识是否正确
- API 密钥是否有效
- 当前网络是否可以访问目标服务
- 相关服务是否仍有可用配额

### 为什么已经保存模型，但功能仍不可用

可能原因包括：

- 模型尚未激活
- 当前项目权限不足
- 数据源页面依赖的是嵌入模型，而你只配置了对话模型
- 保存后未重新进入相关页面或重新发起测试

## 注意事项

- API 密钥属于敏感信息，应妥善保管。
- 修改正在使用的模型后，可能影响已有查询或数据处理任务。
- 建议在正式使用前完成一次实际查询验证，而不仅仅是连接测试。
