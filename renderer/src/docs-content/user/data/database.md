# 数据库管理

数据库管理用于配置项目中的数据库连接，并同步可用于查询的表结构信息。对于依赖结构化业务数据的项目，数据库通常是最基础、最常用的数据来源。

> **权限要求**：需要 `data_manage`（数据管理）权限
>
> **谁有这个权限**：项目管理员、数据管理员角色

## 进入数据库管理页面

**操作路径**：`侧边栏` → `业务管理` → `数据库管理`

## 使用前准备

在添加数据库前，建议先准备以下信息：

- 数据库类型
- 主机地址或文件路径
- 端口
- 数据库名称
- 用户名和密码
- 需要开放给项目使用的目标表范围

如果数据库位于受限网络环境中，还应提前确认网络连通性和访问策略。

## 添加数据库

### 基本步骤

1. 进入数据库管理页面。
2. 新建数据库连接。
3. 选择数据库类型。
4. 填写连接信息。
5. 测试连接并保存。
6. 同步表结构。

### 连接信息说明

| 字段 | 说明 | 必填 |
|------|------|------|
| 名称 | 数据库显示名称 | 是 |
| 描述 | 数据库用途说明 | 否 |
| 主机 | 数据库服务器地址 | 是（除 SQLite） |
| 端口 | 数据库服务端口 | 是（除 SQLite） |
| 数据库名 | 数据库名称 | 是（除 SQLite） |
| 用户名 | 连接用户名 | 是（除 SQLite） |
| 密码 | 连接密码 | 是（除 SQLite） |
| 数据库文件 | SQLite 文件路径 | 仅 SQLite |

### 关于 SQLite

SQLite 为文件型数据库，通常只需指定数据库文件路径，无需填写主机、端口、用户名和密码。

## 同步表结构后应检查什么

保存数据库后，建议在详情页确认以下事项：

- 目标表已成功同步
- 字段名称和字段类型显示正常
- 实际需要参与查询的表处于可用状态
- 不希望暴露给查询的表未被错误纳入

如果表结构同步后缺少关键表，通常需要回到数据库本身检查账号权限、Schema 范围或连接参数。

## 常见管理操作

### 查看表信息

在数据库详情中，通常可以查看：

- 表列表
- 字段结构
- 表的基本说明信息

### 编辑配置

当连接地址、账号或数据库名称变化时，可进入设置页修改配置并重新测试。

### 同步表结构

当数据库中的表、字段或结构发生变化后，应重新执行同步，以便系统使用最新元数据。

### 删除数据库

如果某个数据库连接已不再使用，可将其删除。

> **注意**：删除数据库会移除该数据库的所有配置信息，但不会影响实际数据库中的数据。

## 常见问题

### 连接测试失败时应检查什么

- 主机、端口和数据库名称是否正确
- 用户名和密码是否正确
- 数据库是否允许当前网络地址访问
- 防火墙或安全组是否放行目标端口
- 目标账号是否具备访问目标库的权限

### 查询结果不准确是否一定是模型问题

不一定。数据库连接正常后，如果结果仍不符合预期，更常见的原因是：

- 目标表未被同步或未被纳入可用范围
- 字段名称缺少业务说明
- 指标口径尚未在业务配置中明确

## 注意事项

- 确保数据库服务器允许外部连接
- 建议优先使用权限受控的数据库账号
- 当数据库结构频繁变化时，应定期重新同步
- 完成接入后，建议尽快补充业务语义配置，以提高查询稳定性
