# 结构化数据源

结构化数据源用于接入不直接来自传统数据库、但仍具备明确字段结构的数据，例如 API 返回结果或 CSV、Excel 等表格文件。它适合需要补充外部结构化信息、并希望继续以字段方式进行管理和检索的场景。

> **权限要求**：需要 `data_manage`（数据管理）权限
>
> **谁有这个权限**：项目管理员、数据管理员角色

## 进入结构化数据源页面

**操作路径**：`侧边栏` → `业务管理` → `结构化数据源`

## 使用前准备

开始配置前，建议先确认：

- 项目中已存在可用嵌入模型
- 你已经明确数据来源是 API 还是表格文件
- 你知道数据字段的业务含义和使用范围
- 如果来自接口，已准备好接口地址、请求方式及认证信息

## 什么情况下使用结构化数据源

以下情况通常适合使用结构化数据源：

- 数据来自第三方系统接口，而不是本地数据库
- 数据以 CSV 或 Excel 形式提供，但仍需要按字段检索和管理
- 希望将外部结构化数据纳入项目，作为数据库之外的补充信息源

如果数据已经稳定存放在数据库中，通常优先使用数据库管理，而不是重复建立结构化数据源。

## 前置条件

1. 进入[模型管理](/docs/user/models/management)
2. 确认项目中已有可用嵌入模型
3. 必要时先完成测试和激活

## 创建数据源

### API 数据源

1. 进入结构化数据源页面。
2. 新建数据源。
3. 选择 API 类型。
4. 填写配置信息：
   - 名称
   - API 地址
   - 请求方式
   - 请求头或认证信息
   - 嵌入模型
5. 保存配置。

### 表格数据源

1. 新建数据源。
2. 选择表格类型。
3. 填写配置信息：
   - 名称
   - 数据文件
   - 字段定义
   - 嵌入模型
4. 保存配置。

## 配置数据结构

### API 文档配置

对于 API 数据源，建议尽可能补充接口结构说明，以便系统识别字段来源和数据含义。

如需接入接口类数据，建议同时补充接口描述信息，并检查字段映射结果是否正确。

### 字段定义

对于表格数据源，应尽量明确字段信息：

| 字段 | 说明 |
|------|------|
| 字段名 | 原始字段名称 |
| 显示名 | 在页面和查询中使用的名称 |
| 数据类型 | 字段的数据类型 |
| 描述 | 字段的业务含义 |

## 导入或同步数据

### 添加本地表格文件

对于表格类数据源，可按页面提示选择 CSV、Excel、JSON 等本地文件。系统会记录文件路径并读取原文件进行处理，不会自动把原文件复制到项目工作空间。

### API 同步

对于 API 类数据源，可根据系统能力配置同步频率或手动刷新数据。

## 数据处理与检索

结构化数据源通常既保留字段结构，也可以结合嵌入模型支持语义检索。这意味着你既可以按字段理解数据，也可以在部分场景下进行更灵活的语义召回。

如果检索效果不理想，建议回头检查字段定义是否清晰、数据内容是否完整，以及嵌入模型是否可用。

## 如何验证配置是否可用

配置完成后，建议至少检查以下内容：

- 字段结构是否正确显示
- 样本数据是否已正确导入或同步
- 关键字段名称和说明是否清晰
- 使用相关问题进行测试时，系统是否能正确理解该数据源中的内容

## 管理数据源

### 编辑配置

当接口地址、认证信息、文件内容或字段定义发生变化时，应及时更新配置。

### 数据内容维护

根据页面实际能力，可对已导入数据进行查看、更新或清理。

### 删除数据源

若某个结构化数据源已不再使用，可将其删除。

## 典型使用场景

| 场景 | 说明 |
|------|------|
| 第三方 API | 接入外部系统的 API 数据 |
| 文件数据 | 管理 CSV/Excel 文件数据 |
| 外部补充信息 | 为数据库查询补充额外业务信息 |
| 数据融合 | 整合多个来源的结构化数据 |

## 注意事项

- API 数据源依赖接口稳定性和认证配置，变更后需及时更新。
- 字段定义越清晰，后续查询和检索越稳定。
- 大量导入或频繁同步可能增加处理时间和资源消耗。
