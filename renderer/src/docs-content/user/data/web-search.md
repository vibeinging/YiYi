# 网络数据源

网络数据源用于为项目补充互联网信息检索能力。它通常适用于需要外部公开信息、时效性内容或数据库之外资料的场景。

> **权限要求**：需要 `data_manage`（数据管理）权限
>
> **谁有这个权限**：项目管理员、数据管理员角色

## 进入网络数据源页面

**操作路径**：`侧边栏` → `业务管理` → `网络数据源`

## 什么情况下需要网络数据源

如果问题依赖以下信息，通常可以考虑启用网络数据源：

- 最新新闻、公告、公开资讯
- 互联网公开页面中的补充背景信息
- 项目内部数据无法覆盖的公开资料

如果问题完全依赖项目内部数据，通常应优先使用数据库、结构化数据源或非结构化数据源，而不是网络搜索。

## 使用前准备

开始配置前，建议先确认：

- 你已获得目标搜索服务的访问凭据
- 你了解该服务的费用和调用限制
- 团队已明确哪些场景允许访问外部网络信息

## 配置搜索服务

1. 进入网络数据源页面。
2. 新建或添加搜索服务配置。
3. 填写配置信息：
   - 搜索服务类型
   - API 密钥或认证信息
   - 必要的访问参数
4. 测试连接。
5. 保存配置。

## 配置策略时应考虑什么

### 触发条件

应明确哪些问题需要使用网络检索，例如：

- 问题明显依赖时效性信息
- 问题超出项目内部数据覆盖范围
- 用户明确要求搜索外部资料

### 结果范围

应控制单次检索结果范围，避免返回过多无关内容，增加处理成本和判断难度。

### 时效要求

对于时效性强的信息，可采用较短的缓存策略；对于相对稳定的公开资料，可适当延长缓存时间。

## 使用方式示例

在实际使用中，用户通常会通过带有明确外部信息意图的问题触发网络检索，例如：

```text
搜索今天北京的天气
查询近期公开发布的行业新闻
```

## 如何判断结果是否可信

使用网络数据源时，建议重点关注：

- 是否提供来源信息
- 来源是否可靠
- 信息发布时间是否符合问题要求
- 关键结论是否需要人工复核

## 注意事项

- 网络检索通常会产生额外调用成本，应按需启用。
- 外部公开信息不一定准确，重要结论应结合原始来源复核。
- 对涉敏内容、内部数据或需严格合规控制的场景，应谨慎启用网络搜索。
- 若外部结果与内部数据冲突，应优先核实口径和来源，而不是直接采用任一结果。
